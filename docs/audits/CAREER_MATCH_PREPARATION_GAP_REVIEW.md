# Career Match Preparation Gap Review

Date: 2026-06-21
Phase: `25-career-match-preparation-persistence`
Step: `01-phase-24-output-and-prep-gap-review`
Status: Complete

## Summary

Phase 24 made generated players credible enough to support meaningful manager choices. The next gap is not another content generator pass. The gap is that career fixture advancement still invents the selected club's match preparation at runtime instead of reading a saved manager decision.

The user should be able to inspect the squad, choose a lineup, choose a tactic, persist those choices in the career save, and advance the next fixture using exactly those saved choices.

## Phase 24 Output To Preserve

The player generator now has explicit division and club-tier bands, role-based attribute templates, age/potential archetypes, rarity budgets, and quality tests. This means a career save can now contain players worth inspecting before choosing a lineup.

Useful evidence from the Phase 24 report:

- third-division current ability is no longer broadly inflated;
- off-role values are capped by role template;
- serious prospects and rare prodigies are controlled by league-level rarity budgets;
- `simulate-season --player-generation-report` gives a CLI quality inspection;
- strict `calibration-v1` balance still passes after the generation rework.

## Current Preparation Gap

Career advancement still contains a temporary runtime shortcut:

- `apps/cli/src/commands/career/progression.ts` exposes `advanceCareerNextFixture(careerState)`;
- that function builds every club context from saved roster order;
- selected-club lineup is still generated by `defaultLineupFromRoster`;
- selected-club tactic is still hardcoded to neutral knobs:
  - `directness: 0.5`
  - `pressing: 0.5`
  - `width: 0.5`
  - `risk: 0.5`

This was acceptable before saved preparation existed. It is now the exact shortcut Phase 25 must remove for the manager-controlled club.

Opponent clubs may still use deterministic fallback preparation in this phase because user-controlled opponent preparation is not the current scope.

## Existing Contracts To Reuse

The domain package already has the main language-agnostic contracts:

- `SelectedLineup`
- `SelectedLineupSlot`
- `TacticSetup`
- `createSelectedLineup`
- `createTacticSetup`

These live in `packages/domain/src/entities/tactic.entity.ts`. They validate ambiguity inside the saved choice, but they intentionally do not validate ownership, availability, required lineup size, or role-weight existence.

Phase 25 should reuse these contracts instead of creating a second lineup/tactic model.

## Minimum Durable Preparation Data

The career save needs a small match-preparation slice:

- selected club ID;
- saved selected lineup for that club;
- saved tactic setup for that club;
- optional fixture binding if later steps need fixture-specific preparation;
- update date or current career date when the preparation was saved.

The first durable contract should remain language-agnostic and UI-neutral. It should store IDs and keys, not labels.

## Validation Needed

When saving or loading preparation, the contract should validate:

- the preparation belongs to the selected club;
- every selected player exists;
- every selected player belongs to the selected club roster;
- selected lineup slots are not duplicated;
- selected players are not duplicated;
- tactic values are valid through `createTacticSetup`;
- no hidden automatic lineup or tactic is generated for the selected club.

## Implementation Direction

Step 02 should first add a save-driven squad inspection command so the user can see generated career players before selecting a lineup.

Step 03 should add the durable career-state preparation contract.

Steps 04 and 05 should save explicit lineup and tactic demo choices into that contract.

Step 06 should advance the selected club's fixture only when saved preparation exists, while still allowing deterministic fallback preparation for non-user clubs.

## Non-Goals

This review step did not change product code.

Phase 25 should not add:

- UI screens;
- auto-picking logic for the manager;
- substitutions;
- training;
- youth academy;
- deeper market decisions;
- automatic tactical changes.

## Conclusion

The next implementation work is well-scoped. The selected club must stop using runtime default preparation during career progression and must instead use saved manager choices.
