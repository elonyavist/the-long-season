# 09 - Copy, Localization, And Accessibility Pass

## Goal

Polish matchday wording, localization, keyboard flow, and accessible structure
after the screen hierarchy is rebuilt.

This step turns the interface from functional to product-quality.

## Scope

- Replace debug-like visible labels with football language.
- Ensure every new visible label is localized for:
  - Italian;
  - English;
  - German;
  - Spanish;
  - French.
- Check accessible names for primary commands, phase indicators, event cards,
  tabellino sections, and rating tables.
- Ensure the compact phase indicator does not announce itself as a group of
  buttons.
- Ensure focus order follows the manager's task:
  - score/context;
  - primary action;
  - current phase content;
  - secondary detail.
- Ensure color is not the only signal for goals versus secondary events.
- Update the roadmap Phase 70 progress note.

## What NOT to implement

- No layout redesign unless accessibility exposes a real blocker.
- No new facts.
- No new browser persistence.
- No copy generated by runtime LLM.

- `apps/web/src/features/matchday/CareerMatchdayScreen.tsx`
- `apps/web/src/features/matchday/CareerMatchdayScreen.test.ts`

## Visual check for the user

Review all five matchday phases in Italian and at least one non-Italian locale.

Acceptance:

- labels feel like a football game, not diagnostics;
- phase progress is readable but does not look clickable;
- keyboard focus is visible and reaches the primary action naturally;
- no important event meaning is color-only.

Stop after this step for user approval.

## Definition of Done

- Matchday language is localized and intentional.
- Accessibility issues found during the pass are fixed or documented as
  blockers.
- Status and roadmap are updated.
